# Decision 0026 — Persist authoritative principal memberships in SQLite

- Date/run: 2026-11-17; scheduled IAM persistence slice on `dev`.
- Goal: deliver the first durable piece of the active Phase 2 IAM roadmap: authoritative current principal membership with safe revocation through snapshot reload, plus mutation audit.
- Context: Decision 0025 selected PyCasbin for evaluation but explicitly left mutable authoritative identity and revocation semantics unimplemented. The repository already uses SQLite for its local policy catalog and has no separate IAM database dependency; this slice keeps the local persistence boundary in SQLite and does not introduce a service or package.
- Decision: add `SQLiteIAMStore` with a current-principal JSON snapshot table and append-only mutation event table. Each update and audit record commit atomically. `get_principal`/`list_principals` reconstruct validated immutable Pydantic records; constructing a fresh authorization adapter from `list_principals()` reflects current membership, including removal. Invalid input fails before transaction and no partial audit is written.
- Alternatives: memory-only state cannot survive restart or support authoritative refresh; adding a remote relationship service would be disproportionate and unavailable for this local slice. SQLite is already the canonical local store and needs no new dependency. This is not a claim that JSON snapshot storage is the final normalized multi-entity IAM schema.
