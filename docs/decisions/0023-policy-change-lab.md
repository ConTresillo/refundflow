# Decision 0023 — RefundFlow controlled policy publish-and-retrieve lab

- Date/run: 2026-11-17; scheduled local slice on `dev`.
- Goal: deliver a visible, local policy-change workflow: draft, inspect exact diff, explicitly review, publish a new immutable version and verify it is searchable through canonical SQLite FTS.
- Context: Phase 1 FastAPI shell and gated development identity simulator already exist. The repo has SQLite catalog/FTS ingestion and retrieval. No interactive query API or LangGraph flow exists; this slice is policy administration/retrieval, not query execution. Reuse existing FastAPI/Pydantic/SQLite and in-process TestClient; no dependency additions, vector store, external provider, or network call.
- Alternatives: build separate frontend, add a vector DB, or automatically ingest changed workspace files. Rejected: unnecessary for a small visible local slice; Chroma remains security-gated; silent source synchronization would bypass review. Existing SQLite FTS5 stays canonical.
- Decision: add an opt-in Policy Change Lab, enabled only with `REFUNDFLOW_ENV=development` and `REFUNDFLOW_POLICY_LAB=1`. Seed a persistent local synthetic-policy copy once, never overwrite an existing workspace. Drafts capture base version/hash, proposed immutable version, deterministic diff and diff hash without changing active catalog/index. Publication requires matching diff-hash review and stale-source/catalog checks. The sync operation verifies active chunk and FTS snapshots within the shared SQLite transaction, persists a run report and supports idempotent publish replay. UI supports lexical search after publication.
- Scope limits: immediate publish only; no scheduled effective-date activation, withdrawal/expiry controls in the UI, explicit rollback, conflict explanation, multi-person approval or enterprise authorization. The identity selector remains a development simulator, not OIDC/RBAC. Do not use this lab with real documents or expose it publicly. Filesystem source replacement and SQLite transaction cannot be a single atomic transaction across a process crash; tested failure paths restore prior bytes, but crash recovery is not claimed. No query API/async workflow has been implemented.
- Runnable demo: Windows command from repository root: `set REFUNDFLOW_ENV=development`, `set REFUNDFLOW_POLICY_LAB=1`, `set REFUNDFLOW_DATA_DIR=E:\\RefundFlowData`, then `.venv\\Scripts\\python.exe -m uvicorn app.web:app --host 127.0.0.1 --port 8000 --no-proxy-headers`; open `http://127.0.0.1:8000`, select a seeded identity and visit `/policies`. See `docs/DEMO.md`.
