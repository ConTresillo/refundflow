# Decision 0022 — Phase 1 local app shell and development identity simulator

- Date/run: 2026-11-17; scheduled slice on `dev`.
- Goal: deliver a visible, runnable app shell and a trusted boundary for a local identity simulation without accepting client-selected arbitrary identities/roles as authentication.
- Context: repository already has FastAPI/Starlette and Pydantic; no OIDC client/authentication library (Authlib was absent from the existing venv and lock). Contract requires OIDC for real authentication and permits only clearly gated local development identities until configured. No issuer, client credentials, or OIDC provider was present. FastAPI is already a declared runtime dependency, MIT-licensed; no new dependencies were added. The demo identity selector is intentionally not authentication, and no JWT validation was hand-written.
- Alternatives: add Authlib and configure a local OIDC provider (provider unavailable and adding provider/config now would increase slice scope); build a frontend framework (no existing frontend and unnecessary for a small shell); accept identity headers (rejected: caller-controlled and violates the contract); or defer the visible slice (rejected because a local simulator can be safely gated and transparently labeled).
- Decision: reuse existing FastAPI/Starlette; add a small HTML shell and API; resolve identities exclusively from fixed validated fixture data and server-side opaque in-memory session IDs behind `IdentityPort`. Development mode requires explicit environment selection, runs loopback-only, rejects forwarded proxy headers, uses CSRF and same-origin checks for login/logout, rotates session on login, and defaults to production-disabled mode. Fixture roles are informational, not authorization. No real refund or external service action exists.
- Consequences/limits: the app is runnable without new packages and demonstrates a replaceable identity boundary, not OIDC/production authentication, IAM or authorization. In-memory sessions are lost on restart and the single-worker/no-proxy boundary is documented. `setup-demo.bat` installs project dependencies if needed; `run-demo.bat` binds the dev server to loopback. The existing `.venv` was used for verification; dependencies were not reinstalled.
- Files: `app/web.py`, `app/web_runtime.py`, `app/identity.py`, `app/dev_sessions.py`, `app/dev_identities.json`, `tests/test_web_identity.py`, `tests/test_dev_sessions.py`, `README.md`, `docs/DEMO.md`, `docs/ROADMAP.md`, `pyproject.toml`, `setup-demo.bat`, `run-demo.bat`.
- Dependencies: none added. Authlib is absent in the current venv; a real OIDC integration remains deferred until provider/issuer/client setup and a reviewed compatible OIDC library are selected. No identity credentials are needed for this local simulator.
