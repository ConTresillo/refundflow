# Decision 0046 — bounded digital-PDF parsing and transactional indexing

- Date: 2026-11-19. Goal: add a model-free digital PDF adapter to the existing SQLite catalog/FTS stack without weakening tenant authorization.
- Context: latest `dev` already has authenticated tenant/grant-filtered lexical retrieval and a loopback evidence explorer. The repository's synchronized ingestion boundary only accepts JSON policy sources, so PDF parsing can be integrated into the common catalog/index transaction while retaining API access restrictions.
- Reuse/dependency: chose maintained pure-Python `pypdf==6.4.1` over a custom parser or OCR-heavy package. PyPI metadata reports BSD-3-Clause and no runtime dependencies; official installation docs state Python >=3.10. Runtime supports project Python >=3.10; Windows compatibility is exercised on the configured Python 3.14 venv. Sources: https://pypi.org/project/pypdf/ and https://pypdf.readthedocs.io/en/stable/user/installation.html. No OCR, corpus, or model downloaded.
- Decision: added strict bounded parser, page-located parsed sections, and an ingestion method that activates catalog+FTS together only after complete extraction. Parse errors preserve searchable state and store a per-tenant/document status in SQLite. The API is not wired to accept PDF uploads yet: current seeded IAM grants are read-only, and inventing a write authorization route would be unsafe. Existing authenticated search path remains unchanged.
- Files: `app/document_parsers.py`, `app/policy_ingestion.py`, `app/policy_catalog.py`, parser/ingestion tests, `pyproject.toml`, `requirements-dev.lock`, roadmap and this record. New runtime dependency pinned exactly; lock resolution dry-run passed, `pip check` clean.
- Verification: focused tests `tests/test_document_parsers.py tests/test_pdf_ingestion.py tests/test_policy_ingestion.py tests/test_policy_admin_web.py` — 25 passed; full suite — 105 passed, with 13 existing LangSmith deprecation warnings. Ruff, compileall, pip check, and git diff --check passed. This smoke exercises existing API retrieval, not PDF upload-through-API.
- Parser behavior: text extraction includes `page-1` citation; empty/scanned, encrypted, corrupt, empty, over-8MiB, and over-100-page documents fail closed. Tests prove failed corrupt replacement leaves version 1.0 searchable and records per-file error. Unauthorized empty allow list produces no index candidates. Ingestion fixture currently exercises parser/index and an empty authorization scope separately; a PDF-specific real authenticated API upload/retrieval/tenant-denial path remains outstanding.
- Security/artifact review: parser uses strict mode and static byte/page bounds; no caller-controlled path reaches HTTP. No new upload endpoint was added because safe document-write authorization is absent. Existing owner docs, `.scratch/`, and untracked `var/` preserved and excluded from staging.
