# Enterprise identity, permission-scoped RAG, and async workflow contract

**Status:** Target architecture and acceptance contract; most of these components are not implemented. This is a local enterprise simulation, not a production deployment.

## Why this contract exists

The word “sync” in the recent generation-manifest work refers to the existing *policy/index synchronization transaction*. It does not describe an interactive query endpoint. The repository currently has SQLite catalog/FTS and ingestion/retrieval modules, but no query API, LangGraph query workflow, authentication, authorization, or background worker. An interactive query path therefore cannot yet be called synchronous or asynchronous. It must be designed async-first before it is implemented.

## Identity and authorization model

Model a multi-tenant organization explicitly:

- `Tenant` / organization owns users, groups, roles, documents, cases, jobs, and audit events.
- `User` has a stable subject ID from a validated identity provider and one or more tenant memberships.
- `Group` contains users (and, only if needed, nested groups); memberships can change while work is in progress.
- `Role` grants named permissions such as `document.read`, `case.submit`, `case.approve`, `policy.manage`, and `audit.read`. Assign roles at tenant, group, or resource scope.
- `Document` has tenant, owner, category, sensitivity/classification, business department, effective dates, provenance, and explicit group/user/role grants.

Authentication and authorization are distinct. Use OIDC for authentication; do not write custom JWT validation. Treat token claims as identity hints, not the authority for mutable memberships or document permissions. Authorization decisions must use server-controlled, current membership/policy state and fail closed. Do not trust `tenant_id`, roles, groups, document scopes, or user identity supplied in a request body or generated by the model.

Keep **category**, **scope**, and **permission** separate:

- Category classifies or filters content (for example, `billing-policy` or `risk-guidance`) but does not itself grant access.
- Scope narrows a request (tenant, department, case, date range); a caller may request only scopes that the server confirms they are allowed to use.
- Permission is an authorization result for a principal and resource/action. A document being in the requested category is never sufficient authorization.

Use a mature authorization library/service behind an `AuthorizationPort`; do not accumulate hand-written `if role == ...` checks. Evaluate an embedded engine such as Casbin against relationship-based authorization such as OpenFGA for tenant/group/document grants, including license, operational cost, revocation behavior, local Compose support, and testability. Record the selection in an ADR before adding the dependency. OpenFGA documents tenant and group relationship models[8][9]; Casbin documents domain-aware RBAC and conditional policies[10].

For the local demo, use a clearly marked development identity adapter and seeded users/groups. It must not be enabled in production mode or accept arbitrary user/role headers. The authentication boundary should be replaceable with a standard OIDC provider without changing application authorization code[13].

## Permission-safe RAG

Authorization is part of retrieval, not a UI filter:

1. Authenticate the actor; resolve their current tenant memberships and effective groups/roles server-side.
2. Authorize the requested case and requested scope.
3. Apply tenant and document ACL filters *inside* the lexical/vector candidate query before top-k ranking and before any document text is sent to the model. Do not retrieve global top-k and post-filter it.
4. Rerank and generate only from authorized evidence; validate citations against the same current policy before returning or approving an answer.
5. Recheck authorization when reading a run, resuming a checkpoint, calling a tool, and showing or exporting evidence.

Every document and derived chunk must carry tenant and ACL metadata. Cache keys must include the effective principal/permission version and scope; ACL changes invalidate affected entries. Checkpoints, events, logs, error messages, metrics, and citations must not disclose unauthorized content or reveal cross-tenant document existence. If the authorization engine or ACL projection is unavailable or inconsistent, fail closed—never fall back to model-only answers. OWASP specifically calls out access-control metadata on chunks, tenant/classification isolation, cache isolation, agent-tool controls, and fail-closed behavior for RAG[7].

## Async query and durable background work

The interactive experience is asynchronous in both API behavior and I/O:

- `POST /runs` authenticates/authorizes, persists an idempotent run request, and returns `202 Accepted` with a `run_id` promptly.
- `GET /runs/{run_id}` returns actor-scoped status; `GET /runs/{run_id}/events` streams progress/tokens by SSE (or an equally explicit event contract).
- `POST /runs/{run_id}/resume` submits a validated human decision for a pending interrupt. Only an authorized reviewer may approve; resume is one-time and idempotent.
- A durable queue and separate worker execute the graph. Use a maintained queue library/broker after a short documented fit spike; do not make FastAPI `BackgroundTasks` the only durable mechanism for long-running or resumable work. FastAPI itself distinguishes small same-process tasks from workloads suited to a separate task queue[11].
- LangGraph calls use async APIs (`ainvoke`/`astream`) where supported and a durable checkpointer for interrupt/recovery; the official checkpointer contract persists graph state across invocations[4][5][12]. Sync SQLite operations must be moved off the event loop or replaced by an appropriate async adapter.
- Persist only stable actor/tenant/run IDs and minimum necessary context in queue messages; never put bearer tokens or secrets in jobs. Re-authorize at worker start, before each protected retrieval/tool action, and on resume/output. A job ID is not authorization.
- Specify bounded retries/backoff, leases/visibility timeout, deduplication/idempotency, cancellation, dead-letter handling, queue lag, worker restart, checkpoint recovery, and retention. At-least-once delivery is expected; consequential simulated actions must be idempotent.

Keep ingestion synchronization separate from query execution. It may use a short synchronous SQLite transaction, but parsing, model calls, queue waits, and human approval must never run while holding that transaction.

## Agent and human-review boundaries

Use a bounded, inspectable workflow rather than an open-ended autonomous agent. The model may propose a simulated refund outcome, but server code owns identity, permissions, scopes, policy selection, tool allowlists, approvals, and audit events. Retrieved document text is untrusted input. Tools must be least-privilege, schema-validated, and authorized for the current actor/run. A human interrupt must survive worker restart and re-check the approver's authorization at resume. No real refunds, customer contact, external production tools, or public endpoints.

## Realistic failure and security matrix

Every relevant vertical slice should add tests for its failure modes, including:

- same document IDs/content in two tenants; cross-tenant search, citation, cache, event, and export attempts;
- user removed from a group or role after enqueue, while running, or before approval resume;
- category/scope request that exceeds current grants; stale identity claims; revoked document ACL;
- duplicate, reordered, corrupt, partly parsed, or deleted documents; indexing lag and rollback;
- authorization service unavailable; worker crash before/after checkpoint; duplicate delivery; queue timeout; cancellation; dead-letter and retry exhaustion;
- approval replay, unauthorized approver, concurrent approvals, and resume after terminal state;
- prompt injection in retrieved policy text, tool argument tampering, excessive tool calls, model timeout/rate limit, cache poisoning, and log/trace redaction.

Acceptance must prove non-interference: unauthorized text never enters the model prompt, tool context, cache, output, or logs. Add structured traces and metrics for authorization decisions, retrieval filtering, queue age, retries, graph node duration, approvals, citations, and safe failure categories without logging raw customer/document content.

## Phased, visible delivery

Each phase is a small vertical slice on `dev`, ends with a locally runnable demonstration, tests, and a short operator walkthrough, and is merged to `main` only after CI passes:

1. **App shell and trusted identity:** local UI/API, OIDC/dev identity adapter, tenant-aware request context, health/readiness. Demo switching only among seeded identities; identity is never accepted as arbitrary client data.
2. **IAM and document model:** users, groups, memberships, roles, permissions, categories, scopes, document ownership and grants; deny-by-default policy checks and audit events.
3. **Secure RAG:** ingest categorized synthetic documents with ACL metadata; retrieve only authorized content; show citations, allowed/denied examples, and revocation behavior. Keep the current Chroma security gate.
4. **Async run queue:** durable queue/worker, `202` run API, status/events, idempotence, restart/retry, actor-scoped run access, and async LangGraph calls.
5. **Agent + HITL:** bounded policy-support workflow, least-privilege tools, durable checkpoint, authorized approval/resume, immutable audit trail.
6. **Messy-world hardening:** permission changes during work, stale/missing index, malformed input, provider/worker outages, retries, cache invalidation, prompt injection, evaluation/observability and recovery drills.
7. **Interview-ready breadth:** use the scenario bank in `docs/interviews/AI_SYSTEM_DESIGN_SCENARIOS.md`; design each scenario and map it to a real module, test, or documented trade-off instead of adding unrelated toy subsystems.

The practice scenarios synthesize a public community question bank and official RAG/agent design guidance, not employer-specific hiring data.[1][2][3]
